# Patch provenance boundary

This document classifies the historical Stage 1 research artifacts before they
are converted into public builder inputs. It is an engineering publication
policy, not legal advice.

## Safe to keep in this repository now

- Hashes, sizes, ordered stage identifiers and changed-entry allowlists.
- Project-authored verification, ZIP assembly and test code.
- Normalized Android 13 AOSP Binder-interface signature fixtures used by the
  framework ABI gate. They contain declarations only, no implementations or
  Samsung classes.

## Requires a clean public form

- BC1 manifest/service additions should be expressed as an exact, fail-closed
  transformation against the hash-pinned local stock APK. The historical
  unified diff includes nearby decoded Samsung manifest text and is not the
  preferred publication form.
- BC2 native hooks and BG1 network-statistics changes should be regenerated by
  occurrence-counted transformation code. Their historical unified diffs carry
  decoded stock smali context and must not be copied into this repository.
- The modern MmTel bridge Java appears project-authored, but it still requires
  a final source-by-source provenance and licence review before publication.
- Minimal compile-only Samsung API stubs contain declarations rather than
  implementations. They are useful for interoperability, but remain withheld
  until the project settles their provenance/licensing treatment or replaces
  them with locally generated stubs.

### Bridge-source audit

The historical generator mechanically produces `ModernCallRelay.java` and
`ModernCallSession.java` from the two Android 13 AOSP Binder ABI listings plus
project-authored relay/delegation templates. No Samsung method implementation
was found in either generated adapter.

`GoogleModernImsService.java`, `GoogleModernMmTelFeature.java`,
`ModernEventQueue.java` and `ModernVoiceContext.java` have the structure of
project-authored service, ownership and queue state machines; the audit found
no decompiler markers or copied Samsung method bodies. They remain withheld
until their authorship/licence record is finalized. `ModernVoiceContext.java`
has the widest dependency on Samsung private API declarations and therefore
receives the strictest review.

The six historical `compile-only` Java files are generator literals containing
minimal Samsung API projections and dummy bodies. They are not runtime payload,
but their current checked-in-like form is not a publication input. Two methods
in the `GoogleImsService` projection, `getInstanceIfReady()` and
`getModernIncomingIdentity(int)`, are project-added hook contracts rather than
stock declarations and must be identified as such.

### Planned local stub generation

The public builder will generate compile-only stubs in a private temporary
directory from user-supplied, hash-pinned stock APK/JAR inputs. Extraction is
limited to an allowlist of class/superclass names, method access flags, names,
descriptors and declared exceptions. It must not copy instructions, fields,
line tables, parameter names or neighboring decoded content.

Every expected class and method must occur exactly once and match its declared
descriptor. Project-added hook contracts are merged from a separate
project-owned specification only after the patcher verifies those hooks were
inserted. Fixed dummy bodies are generated solely for compilation, the output
is excluded from the candidate DEX, a leakage gate checks the final APK, and
the temporary stubs are deleted after use.

### Implemented compile-stub boundary

`devices/m11q/compile-stub-contract.json` records the exact six historical
compile-only class projections. Stock declarations and the two project-added
`GoogleImsService` hooks are deliberately stored in separate arrays. The hooks
are labelled with project provenance and must also occur exactly once in the
already-patched private smali input; the generator never silently invents them.

`tools/generate_compile_stubs.py` accepts named smali roots supplied by the
outer, hash-pinning workflow. It reads only the allowlisted class files and
retains only class/superclass, method name, descriptor, access flags and the
minimal `dalvik.annotation.Throws` declaration. Generated Java uses synthetic
`arg0`, `arg1`, ... names and fixed dummy bodies. Instructions, fields, line
tables, locals and original parameter names cannot enter the output or report.
The observed stock superclass is independently verified for drift; it is not
automatically inherited by generated Java. The contract exposes a separate
`java_super` only where bridge compilation actually requires that relationship.

Decoded directories must remain in a private temporary directory covered by
`.gitignore`; do not point the tool at a directory intended for publication.
Generated stubs and their report are disposable local build artifacts: never
commit them, never add them to the bridge source set passed to D8, and never
place their classes in candidate `classes.dex` or `classes2.dex`. The future
orchestrator remains responsible for verifying the input artifact hash before
decoding and for deleting all temporary inputs and generated stubs afterward.

Example (paths are deliberately placeholders):

```text
python tools/generate_compile_stubs.py \
  --contract devices/m11q/compile-stub-contract.json \
  --smali-root imsmanager=PRIVATE_TEMP/imsmanager/smali \
  --smali-root imsservice=PRIVATE_TEMP/imsservice/smali \
  --output PRIVATE_TEMP/compile-stubs \
  --report PRIVATE_TEMP/compile-stub-report.json
```

The default is non-overwrite. `--allow-identical` makes a repeated invocation
idempotent only when every existing generated byte and the report are already
identical; a conflict is never replaced.

### Implemented BC2 native-hook boundary

`devices/m11q/bc2-native-hooks-contract.json` contains only the three target
class/method descriptors, required field identities, hook identities and exact
occurrence expectations. It intentionally contains none of the surrounding
Samsung method implementation that appeared in the historical unified diff.

`tools/transform_bc2_native_hooks.py` reads exactly those three files from a
private apktool-decoded smali root and emits an independent three-file overlay.
It validates the class, superclass, fields, target methods, anchors, register
capacity and pre/post hook state; drift, an already/partly applied input, or a
hook outside its allowlisted method fails closed. It does not expect or remove
the obsolete BC1 discovery skeleton classes. Its report contains relative
allowlisted paths, hook IDs and hashes only—not source text or local paths.

The overlay still contains transformed Samsung smali and is a disposable local
build artifact. It is gitignored and must not be published. See
`docs/BC2_NATIVE_HOOKS.md` for the isolation and validation rules.

## Never publish

- Stock, intermediate or patched APK/JAR/DEX/class files.
- Decoded Samsung trees or generated smali inventories.
- Samsung daemons, shared libraries, firmware or partition images.
- ROM signing keys, private runtime captures or subscriber identifiers.
- Historical build directories, backups and absolute-path scripts.

## Publication gate for each transformation

A transformation may be added only when it starts from the declared stock
hash, checks every target and occurrence count, makes only allowlisted entry or
method changes, fails closed on drift, and has synthetic tests containing no
Samsung implementation. Generated output remains local and gitignored.

Passing these source and structure checks does not make a new APK runtime
validated. A newly packaged candidate still requires a manual ROM build/flash
and the separately documented on-device acceptance tests under SELinux
Enforcing.
